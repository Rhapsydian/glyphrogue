## Key decisions

- **`ctx.rng` is the exact same live object as `api.rng`, not a derived
  copy** — confirmed live via `AskUserQuestion`, per `BACKLOG.md`'s own
  "confirm/adjust live" flag on this shape. The alternative (seed a new
  rng from `api.rng.state` at engine-creation time, then let it diverge)
  was presented explicitly as the thing to rule out — it reproduces
  exactly the bug glyphkeep's own `combatRng` workaround already has
  today (a frozen-at-startup copy that silently drifts from `api.rng`
  once anything else, like map generation, calls `.next()` first). Shared
  identity also matches `save.js`'s existing `api.rng.state` serialization
  and `mapgen.js`'s generator-ctx shape (`{ rng, params, ... }`) that
  `ctx.rng` mirrors.
- **`rng` is appended *after* `devMode`, not before, in every changed
  signature** (`createContext`, `dispatch`, `dispatchExclusive`,
  `createEngine`). Found by grepping every call site before deciding: the
  more natural-looking placement (before `devMode`) would have silently
  broken `actions.test.js`'s existing devMode tests (lines 529-584), which
  call `dispatch(..., undefined, undefined, undefined, true)` to hit
  `devMode` positionally. No call site anywhere passes `devMode`
  positionally into `createEngine`, so that append was safe by the same
  reasoning.
- **No no-op wrapping for an omitted `rng`** — unlike `renderEvents`/
  `scheduler`'s no-op-callback treatment, `ctx.rng` is simply `undefined`
  when never supplied. A rule that doesn't touch `ctx.rng` is unaffected;
  one that does and gets nothing behaves the same as `mapQuery`'s
  `isWalkable`/`isOpaque` already do when omitted.

## Deferred / parked

The actual glyphkeep fold-back (retiring `combatRng` for `ctx.rng`, and
`isWalkableInZone`/`isOpaqueInZone`/`cellAt` for the exported
`isWalkableCell`) is a separate, glyphkeep-side session, next up per both
repos' `BACKLOG.md`. Two things flagged there so they aren't re-derived:

- Folding back the combat rng changes actual combat-roll behavior, not
  just the code — `Attack` will consume the same live stream as map
  generation instead of a stream frozen at bootstrap.
- `isWalkableCell` (`!== 'wall'`) and glyphkeep's `isWalkableInZone`
  (`=== 'floor'`) aren't semantically identical — a `'door'` cell is
  walkable under the former but not the latter (used in
  `zoneComposition.test.js`'s own fixtures), so the swap isn't guaranteed
  to be a drop-in no-op if glyphkeep's zones gain a non-floor walkable
  cell type.

Not bundled: `stampTemplate`/`runConnectivityPass` are also currently
missing from `index.js`'s export list, discovered while checking the
`isWalkableCell` export site, but out of scope for this session (and
`runConnectivityPass` isn't needed until glyphkeep's Phase 5 per its own
`BACKLOG.md`).
