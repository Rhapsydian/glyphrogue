## Key decisions

- **`spend()` throws rather than corrupting state for an unregistered
  entity.** `engine.js`'s comment on the already-fixed empty-scheduler
  hang had already half-noticed "`spend()` has no existing-actor guard
  either," but that earlier fix only guarded `act()`'s
  `entity === undefined` case, not `spend()` itself. glyphkeep's Phase 3
  hit the gap from a different angle: `api.closeScreen` →
  `resolvePlayerAction` → `spend`, called with a *valid* entity that
  simply hadn't been `addActor`'d yet in some call orderings. A thrown
  error was the right call here (not a graceful idle-return like `act()`'s
  fix) — this is caller error, not a legitimate empty-scheduler state.
