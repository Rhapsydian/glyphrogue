## Key decisions

- **Export `fleesRule` raw, not just the pre-wrapped `fleesPlugin`.**
  glyphkeep's slime archetype needed "aggressive until hurt, then flees" —
  achievable by reusing the real, tested flee-movement logic with a
  tighter `registerRule` component filter (marker present AND health at
  or below a threshold), but only the pre-wrapped plugin (a fixed,
  unconditional `all: ['Flees']` filter) was public. The four priority
  constants and `DEFAULT_MOVE_COST` travel with it — a downstream rule
  composing with the real behaviors needs the actual priority ordering and
  turn-cost value, not a hardcoded number that silently drifts if either
  is ever retuned (glyphkeep had independently redeclared "100" twice for
  exactly this reason, once discovered).
- **Only `wandersRule`/`chasesPlayerRule`/`guardsRule` stay unexported for
  now** — nothing in glyphkeep needs a tightened filter around those yet.
  Export them too the day something does, same "wait for a real consumer"
  posture as everything else in this backlog.
